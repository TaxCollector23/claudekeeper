You stepped away. Your Mac took that as permission to quit.

Claude Code lives in your terminal, and your terminal lives at the mercy of your Mac's power state. It is doing real work — a long refactor, a test suite, an agent grinding through a plan — right up until you close the lid. Then macOS sleeps, the process is suspended, and the session just… stalls. Nothing outside that one window is keeping it alive.

Which is a strange thing to accept from a machine that was, a second ago, perfectly capable of finishing the job. The work didn't fail. It didn't error out. It got paused by the hardware because a hinge moved a few degrees.

The task was never the problem. Sleep was.

So you reach for the usual tricks. The honest part is that most of them don't survive a closed lid — they hold off the idle timer and nothing more:

  • Just leave the terminal open and hope.
  • Run caffeinate in another tab.
  • Hold an idle sleep assertion.
  • Tell yourself it's probably fine in your bag.

Every one of those keeps a Mac awake while the lid is up and the idle clock is ticking. None of them override the clamshell switch. Close the laptop and macOS sleeps anyway — assertions and all. There is exactly one setting that outranks lid-close sleep, and it is pmset disablesleep 1. That's the whole trick. That's the part everyone skips because it needs sudo.

ClaudeKeeper does the unglamorous, correct thing.

It's a tiny local daemon that holds a real sleep assertion so the Mac never idle-sleeps, and then — the part that actually matters — flips disablesleep so the machine stays fully awake with the lid shut: screen off, CPU on, your Claude process still running. It asks for sudo once, it tells you exactly what it changed, and it puts everything back when you stop it.

How it keeps the Mac awake — the real mechanism.

No magic, no kernel extension. A small local daemon and two power settings, applied in the open and restored when you stop. Here is exactly what runs.

Step 01

The daemon owns it.

You start it once. A tiny local daemon runs independent of your terminal — close the shell, the daemon stays up. It prints the port it serves on for an optional dashboard.

$ claudekeeper daemon start
→ serving http://localhost:7642
Step 02

Idle sleep — held off.

It holds a real sleep assertion (native IOKit, the same kind caffeinate uses) so the Mac never idle-sleeps while it works. You can see it yourself — no sudo for this part.

$ pmset -g assertions
PreventUserIdleSystemSleep 1
 (claudekeeper)
Step 03

Lid close — the real fix.

This is the part nothing else does. It runs one command behind a single sudo prompt — the only setting that overrides lid-close sleep. Lid shut, Mac fully awake, Claude keeps running. Restored on stop or uninstall.

$ sudo pmset -a disablesleep 1

assertion: idle-only  disablesleep: on

The honest caveat An idle sleep assertion alone does not survive lid close — that is why Step 03 exists, and why it needs sudo. And a closed Mac that never sleeps makes heat: run it on AC power, on a hard surface, and don't cook it shut in a bag. Prefer idle-only and skip the sudo? Start it with --no-lid.

The whole surface is three commands.

No config file, no dashboard to learn. Install it once, then start, stop, or remove it. That's the entire manual.

Install
macOS · Node 24+ · one global package.
npm install -g @rangan23/claudekeeper
claudekeeper daemon start

Start the daemon and keep the Mac awake — lid closed included. Prints the port it serves on.

claudekeeper daemon stop

Stop the daemon and restore normal sleep.

claudekeeper uninstall

Stop, restore sleep, and remove it. No trace left behind.

Don't want the sudo prompt? Add claudekeeper daemon start --no-lid for idle-sleep only — it keeps the Mac awake while the lid is open, no password required. Close the lid and it sleeps as usual.
